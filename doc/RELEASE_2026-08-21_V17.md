## 1. v17 是什么

v17 = **实机验证通过的运行态快照**。构建方式：从验证通过的 sys2（v16 开发线）直接提取
运行中的 rootfs（squashfs）+ overlay 全部修复层，合并后重新打包，
ubinize 使用 v15 验证过的三卷布局（mtd-utils 2.1.1）。

与 v15/v16 的区别：v17 里的每一项修复都在实机上跑过，不是"应该能工作"。

## 2. v15 → v17 修复清单（全部实机验证）

### LuCI 25.12 数据链路
| 问题 | 根因 | 修复 |
|---|---|---|
| uhttpd 崩溃循环 "Unable to connect to ubus socket" | /etc/config/uhttpd 的 ubus_socket 指向错误路径 | 设为 `/var/run/ubus.sock` |
| /ubus 所有请求 "Parse error" | 新 uhttpd（json-c.so.5）与旧 libblobmsg_json（json-c.so.2）同进程符号冲突 | **库分离**：旧库留在 /lib（rpcd/procd/ubus CLI 用），新库放 /usr/lib2，uhttpd init 脚本加 `LD_LIBRARY_PATH=/usr/lib2` |
| ubus CLI/procd service set 全部 Invalid argument | 同上（CLI 用新库编码 blob 失败） | 同上，/lib 恢复旧库后自动恢复 |
| 概览页完全空白 | **rpcd-mod-file 缺失**，概览页靠 `file list` 扫描 include | 部署 rpcd-mod-file.so（2020 版，与旧 rpcd 同版本） |
| rc/list、luci/getFeatures 报错 | /usr/libexec/rpcd/ 插件目录整个缺失 | 新增自写 shell 插件 `rc`（list/init）+ v15 提取的 `luci` 插件并补齐 getUnixtime/getVersion/getBuiltinEthernetPorts |
| network.wireless status Access denied | 缺 root 全权 ACL | 新增 /usr/share/rpcd/acl.d/root.json |
| iwinfo 对象缺失 | rpcd-mod-iwinfo 未装 | 部署 rpcd-mod-iwinfo.so |
| 网络页"网桥配置迁移"弹窗挡页 | 老 netifd 不支持新 device/ports 语法，迁移=断网 | interfaces.js 打补丁禁用迁移弹窗（`if(false)`），保持旧式配置 |

### WiFi
| 问题 | 根因 | 修复 |
|---|---|---|
| 2.4G 搜不到（VAP 假死） | ① `/lib/wifi/qcawificfg80211.sh` 缺 sysfs phy 路径补丁；② **`/lib/firmware/IPQ6018/caldata.bin` 射频校准数据缺失**（v13.8 打包时就丢了） | 部署 sys1 补丁版脚本 + 从实机 ART dump 的 caldata.bin 烘入镜像（冷启动时就位） |
| WiFi 开机自启 | QSDK fastboot 时序 | rc.local `sleep 10; wifi up` + NSS offload 配置（olcfg=3/olnum=2） |

### 系统
| 问题 | 修复 |
|---|---|
| dnsmasq 崩溃循环（连不上网/无 DHCP） | **libnettle.so.8/libhogweed.so.6 丢失**（v13.8 打包时即丢失），从原始 NWRT rootfs 找回 ARM 实体库 |

## 4. 刷写方法（双分区安全流程）

**必须从对侧分区刷**（运行在 sys1 就刷 mtd19，运行在 sys2 就刷 mtd18）：

```sh
# 假设当前运行 sys1，刷 sys2(mtd19)：
scp ax5-32bit-v17.0-release.ubi root@192.168.1.1:/tmp/v17.ubi
ssh root@192.168.1.1
ubiformat /dev/mtd19 -f /tmp/v17.ubi -y
fw_setenv flag_boot_rootfs 1
fw_setenv flag_try_sys1_failed 1   # 关键：强制切到 sys2
fw_setenv flag_try_sys2_failed 0
sync; sleep 3; reboot
```

> 教训（v17 开发时踩的坑）：
> 1. 运行中的分区不能 ubiformat 自己（mtd 被 ubi 挂载会报错，但后续 fw_setenv/reboot 仍会执行——刷写失败时必须中止后续步骤）。
> 2. 切分区靠 `flag_try_sysX_failed=1`，不是只靠 `flag_boot_rootfs`。
