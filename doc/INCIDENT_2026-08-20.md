## 2. 根因分析

### 2.1 NWRT 32-bit 内核驱动模式: **ACFG-only**

NWRT (QSDK 12.2) 内核中的 `wifi_3_0` 驱动是 **Atheros Configuration (ACFG) 私有协议**,**不是** 标准 Linux `nl80211`:

| 现象 | 含义 |
|---|---|
| `/sys/class/ieee80211/phy0/` 不存在 | 驱动不导出标准 Linux cfg80211 phy |
| `/sys/class/net/wifi0/phy80211` 不存在 | 没有 cfg80211 netdev link |
| `hostapd -dd` 报 `Driver does not support authentication/association` | hostapd nl80211 路径完全不能走 |
| `wlanconfig ath0 create ... -cfg80211` 报 `Invalid tag '-cfg80211' for current mode` | 驱动不接受标准 CFG80211 VAP 创建 |
| `cfg80211tool` 工具存在但所有命令返回 `Unknown Command : 25` | 工具的 CFG80211 函数没有编译进这个驱动 |
| `acfg_tool` 有 916 行 API 文档,功能完整 | **这条路径才走得通** |

### 2.2 v13 编译时漏掉了 246KB CFG80211 脚本

对比:
- **备用分区 (NWRT 原厂)**: `/lib/wifi/qcawificfg80211.sh` 246KB,**完整** CFG80211 流程脚本
- **我们的 v13**: `/lib/wifi/qcawificfg80211-disabled.sh` 246KB,**但是是占位空壳**

检查发现我们裁剪时把真正的脚本**漏掉了**,只复制了 ACFG 用的 `qcawifi.sh` (148KB)。这就导致:
1. `wireless` config 写 `type qcawificfg80211` 时,`/sbin/wifi up` 调 `enable_qcawificfg80211` 函数 → 失败 (`-cfg80211` tag 不接受)
2. `wireless` config 写 `type qcawifi` 时,`/sbin/wifi up` 调 `enable_qcawifi` 函数 → 但驱动模式不匹配,卡死在 `Invalid command : hide_ssid`

### 2.3 禁忌操作清单

| 操作 | 后果 |
|---|---|
| `kill -9 -f wifi` 当 wifi 持 wifilock 时 | 驱动内核态持锁,被 KILL 后软锁死,第二次再 KILL 会 kernel panic |
| `ip link set ath0 up` (对 ACFG VAP) | 驱动 panic,需要 reboot |
| **`acfg_tool acfg_set_freq ath0 5745`** (在 VAP 已绑定 br-lan 之后) | ⚠️ **触发 driver SSR (System SubSystem Reset),wifi0/wifi1 永久 DOWN,需要 reboot** |
| 强行 `rmmod wifi_3_0` 或 `qca_ol` | 同上,内核态崩 |
| `/sbin/wifi up` 带 `type qcawificfg80211` | 死锁在 `phy80211/name` sysfs 不存在 |
| `/sbin/wifi up` 带 `type qcawifi` | 死锁在 `Invalid command : hide_ssid` |
| `iw phy phy0 interface add ath0 type __ap` | `nl80211` 路径在 ACFG 驱动上完全不通 |

### 2.4 driver 模式判断方法

```bash
# 1. 看 sysfs 有没有标准 cfg80211 phy
ls /sys/class/ieee80211/   # 空 → ACFG-only
ls /sys/class/net/wifi0/phy80211  # 不存在 → ACFG-only

# 2. 看 hostapd 是否能 nl80211 启动
hostapd -dd -t /tmp/test.conf  # "Driver does not support authentication/association" → ACFG

# 3. 看 wlanconfig 是否接受 -cfg80211 flag
wlanconfig ath0 create wlandev wifi0 wlanmode ap -cfg80211
# "Invalid tag '-cfg80211' for current mode" → ACFG

# 4. 看 acfg_tool API 数量 (ACFG 驱动 ≥ 800 行 API)
acfg_tool -p | wc -l   # 916 → ACFG
```

## 3. 正确的 WiFi 启动流程 (ACFG-only 模式)

按 NWRT 的设计,**boot 时不调用 wifi up**。需要手动逐步配:

```bash
# 1. 确认 wireless config 走 qcawifi (ACFG)
uci set wireless.wifi0.type=qcawifi
uci set wireless.wifi1.type=qcawifi
uci commit wireless

# 2. 手动建 VAP (不带 -cfg80211 flag)
wlanconfig ath0 create wlandev wifi0 wlanmode ap
wlanconfig ath1 create wlandev wifi1 wlanmode ap

# 3. ⚠️ 不要在这里调 set_freq -- 5G 默认 chan 36, 2.4G 默认 chan 1
#    set_freq 触发 driver SSR,只有 reboot 才能恢复
#    如果一定要换频道,只能重新刷机换带 qcawificfg80211.sh 完整脚本的 rootfs,
#    然后用 hostapd nl80211 路径,或者改 ini 文件后重新生成 rootfs。

# 4. 通过 acfg_tool 配置 vap (ssid/security)
acfg_tool acfg_set_ssid ath0 Nwrt_5G
acfg_tool acfg_set_ssid ath1 Nwrt_2.4G

# 5. 配 WPA2-PSK
acfg_tool acfg_hostapd_set_wpa ath0 2 "wpa_passphrase=12345678" WPA-PSK CCMP 86400
acfg_tool acfg_hostapd_set_wpa ath1 2 "wpa_passphrase=12345678" WPA-PSK CCMP 86400

# 6. 把 ath0/ath1 加进 br-lan
brctl addif br-lan ath0
brctl addif br-lan ath1

# 7. ⚠️ 千万不能 ip link set ath0 up -- acfg 自己会 up
```

**结论**:在当前 ACFG-only 模式下,**5G 只能跑 chan 36,2.4G 只能跑 chan 1**。要支持其他频道,**必须刷一个带真正 CFG80211 路径的 rootfs** —— 那是 v10 修补要做的事。

## 5. 不要做的事 (硬规则)

1. ❌ **`kill -9` 任何 wifi 进程** —— 包括 `wpa_supplicant`/`hostapd`/`wlanconfig`/`cfg80211tool`/`acfg_tool` 等等。持锁进程被 KILL 后会进 driver kernel panic。
2. ❌ **`ip link set athX up`** —— ACFG 驱动自己负责 VAP up,Linux netdev up 会触发 driver 内部状态机不一致。
3. ❌ **`iw phy phyX interface add athX type __ap`** —— 驱动无标准 cfg80211 phy。
4. ❌ **`rmmod wifi_3_0 / qca_ol / umac / qdf`** —— 任何 wcss 模块 unbind 都会让 WCSS 协处理器下电。
5. ❌ **`ubiformat /dev/mtd19` 直接刷新 ubi** —— 会清空 rootfs_data overlay,jffs2 上 12 MB 已配置全丢。刷完用 fw_setenv 把 flag 修正好。
6. ❌ **`/sbin/wifi up`** (任何时候,即使 type 改对了) —— NWRT 这个版本 wifi up 自身会死锁在某些命令上,改用 `wlanconfig create` + `acfg_tool` 手动流程。

## 7. 经验教训 (留给未来的自己)

1. **裁剪 WiFi 用户态脚本时,要对照源 rootfs 完整文件清单** —— 不是看大小,要看 `/lib/wifi/` 下的每个脚本是否被 `/sbin/wifi` 调用链需要。
2. **/sbin/wifi up 是高风险动作** —— 在 NWRT 这种深度修改的固件中,wifi up 牵涉驱动交互 + 持锁 + 多脚本串联,任何中断都会破坏内核状态机。
3. **遇到 driver 不接受某 flag 时,先 grep 全 grep "-cfg80211"** —— driver 是 ACFG 还是 CFG80211 一次确认终生受益。
4. **kill -9 是大锤,能不用就不用** —— 在嵌入式路由器上,wifi 进程挂死时宁可 `reboot` 也不要 kill -9。
5. **任何禁忌操作之前**:**先备份 fw_printenv 输出,记录 flag_try_sysN_failed 状态**,这样能确保 sys1/sys2 还能回滚。
